# 评测说明

## 结论先行

当前可复现的评测对象是**离线关键词规则**，不是 DeepSeek 语义模型。

规则冻结后的发布测试集结果：

- 样本数：28
- Accuracy：57.1%
- Macro F1：58.5%

这个结果不高，但它避免了用调参过拟合后的 100% 误导面试官。项目通过较差的规则泛化结果说明：真实反馈分析需要模型语义理解，规则更适合作为无 Key 演示和模型故障兜底。

| 数据集 | 数量 | 是否参与调规则 | 结果 | 解读 |

## 测试方法

每条反馈只有一个主主题，共 7 类：

- 稳定性与故障
- 使用体验
- 功能需求
- 价格与订阅
- 内容与效果
- 客户服务
- 隐私与安全

运行方式：

```bash
python3 scripts/run_eval.py data/release_test_feedback.csv
```

脚本输出 Accuracy、Macro F1、正确数量、混淆情况和具体误分类样本。

## 发布测试中的主要失败

未参与调规则的测试集暴露了四类问题：

1. **同义表达覆盖不足**：例如“服务像挂了”“内容突然消失”无法稳定进入稳定性主题。
2. **功能请求与使用体验交叉**：“能不能简化步骤”既可能是新功能，也可能是体验优化。
3. **隐式内容质量问题**：“看不出差异”“和账号定位不搭”没有直接出现“内容”或“质量”。
4. **权限问题的表达多样**：“链接一直有效吗”“哪些设备登录过”需要语义和上下文判断。

这些问题不是继续堆关键词就能高质量解决的，因此产品选择是：

- 引入大模型做逐条语义分类。
- 固定分类枚举并校验输出。
- 无 Key 或模型失败时回退到规则。
- 高风险或低置信度结果进入人工审核。
